BRIEFING 01

Start with the one difference that matters

Both systems inspect traffic. Their position and permitted action are different.

IDSOBSERVES

Intrusion Detection System

What: A security control that monitors traffic or events and creates alerts when activity matches a detection condition.

Why: It gives analysts visibility without normally sitting in the direct path of the connection.

How: A network tap or mirrored switch port sends the IDS a copy of traffic. The original traffic continues.

TrafficDestinationcopy to IDS
IPSINLINE

Intrusion Prevention System

What: A security control that inspects traffic in the connection path and can take a configured prevention action.

Why: It can stop selected harmful traffic before the traffic reaches its destination.

How: Every packet passes through the IPS. A rule may allow, drop, reject or alert according to policy.

TrafficIPSDestination
01An alert is a clue

It is not automatic proof of an attack.

02Context changes meaning

Asset role, user, time and approval matter.

03Blocking has impact

A poor IPS rule can interrupt legitimate work.

04Notes protect hand-offs

Record evidence, actions, unknowns and reason.

BRIEFING 03

How a signal becomes an alert

Detection logic highlights patterns. The analyst still has to test the meaning.

02DecodeRead protocol and fields

SIGNATURE

Known pattern

Looks for a defined byte, protocol or request pattern. Precise signatures can be useful, but small changes or harmless matching text may affect results.

pattern matched = alert
BEHAVIOUR

Unusual activity

Compares current behaviour with a rule or baseline, such as one device contacting many ports in a short period.

unusual rate = alert
POLICY

Forbidden condition

Checks an organisational rule, such as inbound remote desktop traffic from the internet to an office device.

policy violation = alert

CASE SJ-2207

Unusual activity on FIN-LT-07

Three sensors observed related activity during a six-minute window.

STATUSNeeds analyst decision
14:02
IDS
Rare DNS query

10.20.5.88 queried update-check.example. The domain is new in this fictional environment.

ACTION: ALERTED, NOT BLOCKED
14:05
EDR
Unexpected child process

The archive viewer on FIN-LT-07 started an unsigned process from the user's temporary folder.

ACTION: PROCESS OBSERVED
14:08
IPS
Outbound connection prevented

The same endpoint attempted TCP/443 to 203.0.113.90, which matched the lab's high-confidence block rule.

ACTION: DROPPED BY IPS

Known

  • All three events involve FIN-LT-07 / 10.20.5.88.
  • The IPS dropped the 14:08 connection.
  • The process chain is unusual for this endpoint.
  • No approved change is shown.

Still unknown

  • Whether the user opened an expected file.
  • Whether any earlier connection succeeded.
  • What the unsigned process changed.
  • Whether another endpoint shows the same pattern.

Use only facts shown on the board. Distinguish alerted from blocked, preserve evidence, state what remains unknown, and escalate according to the playbook.
